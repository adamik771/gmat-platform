# Chapter 3.5 — Multi-Source Reasoning

## Core idea

Multi-Source Reasoning (MSR) is the *most information-dense format on the GMAT*. A typical MSR set gives you three or four tabs — some text, some tables, some charts — and asks three or four questions about the data, often requiring synthesis across two or more sources. The information volume exceeds what you can hold in working memory. The skill is *building a source map* — knowing which tab contains which kind of information — and *querying the map on a per-question basis*, returning to specific tabs as questions demand.

The mindset shift in this chapter: *don't memorize; map*. You will not retain the data. You will retain the *organization* — which tab has cost data, which has volume data, which has narrative context — and use that map to navigate efficiently when each question fires.

## Why it matters

Three reasons MSR deserves dedicated treatment.

*MSR has the largest score variance of any DI format*. Students either learn the source-map discipline or they don't. The ones who do score in the 90th-plus on MSR; the ones who don't score in the 50th-60th. The variance is almost entirely about navigation skill, not content knowledge.

*MSR rewards transferring multiple section skills*. Verbal-style structural reading on the text tab. Quant-style computation on the table tabs. Information-triage from the DI mindset chapter. Strong MSR solvers integrate these; weak solvers compartmentalize.

*MSR has the highest pacing risk in DI*. A botched MSR set can consume eight or nine minutes on a section that has a 45-minute total. That's enough to crash pacing on the next ten questions. Strong solvers respect the budget; weak solvers grind.

## Mental model

Treat every MSR set as a *small organized resource collection* with three or four distinct shelves. The text tab is narrative — context, definitions, scenario setup. The table tabs are quantitative — data broken down by category or time. The chart tabs are visualizations — trends, comparisons, distributions. Each shelf has a known type of content, and your job is to know which shelf has what.

The work on first encounter is to *catalog* the collection, not to read it. Walk each tab briefly, note the kind of resource, and commit the organization to memory. Don't try to read every book on every shelf; you'll be back. Just know: "the cost data is on shelf 2; the volume data is on shelf 3; the company description is on shelf 1."

When each question comes, you go directly to the right shelf, find the specific information needed, use it, and move on.

## GMAT recognition signals

Five recurring MSR set structures.

*Description + tables.* One narrative tab introducing a scenario; two or three tabs of tabular data. Common in business cases.

*Tables + chart.* Two tabs of tables (e.g., production and cost) and one chart tab (e.g., trends). Common in operational analysis problems.

*Email + report data.* One tab is a memo or email; subsequent tabs are referenced data. Common in decision-making problems.

*Article + supplementary data.* One tab is a longer text passage; subsequent tabs are supporting tables or figures. Common in analytical-essay-style problems.

*Multiple short sources.* Each tab is brief — a paragraph, a small table, a chart — and the questions require pulling pieces from multiple tabs. Highest synthesis demand.

## Method

A four-step MSR protocol.

*Step 1. Walk the tabs (60-90 seconds for the whole set).* Briefly read each tab — five to fifteen seconds per tab — to *catalog* what's there. Note: which tab has narrative? Which has tabular data? What columns does each table have? What does each chart measure? Build the source map.

*Step 2. Read the first question and identify the relevant tab(s).* The question's vocabulary usually points to specific data — "cost," "volume," "growth rate," "percentage of." Match the vocabulary to the tab.

*Step 3. Process only the relevant data.* Return to the tab(s) the question targets. Read carefully. Compute or compare as needed. Ignore everything else.

*Step 4. Move to the next question.* For subsequent questions, skip Step 1 (you already cataloged the library) and go directly to Steps 2-4. This is where the source map pays back — each question after the first costs less navigation time.

The total budget for an MSR set: approximately 7-9 minutes for three to four questions. The first question typically costs the most (because of the tab-walking phase); subsequent questions get faster.

## Common traps

Six recurring MSR traps.

*Reading every tab in full on first encounter.* The instinct to "really understand the data" before answering. Burns the time budget. Fix: catalog, don't read.

*Switching tabs constantly during a single question.* Going back and forth between tabs because you're not sure where the information is. Fix: identify the target tab from the question's vocabulary first, then go directly there.

*Forgetting the source map between questions.* Re-cataloging on every question. Fix: load the map once, reuse it across all questions in the set.

*Confusing units across sources.* Tab 1 reports revenue in millions; tab 2 reports it in billions. Mixing these gives wrong answers. Fix: explicitly note units when querying each source.

*Synthesizing wrong data.* The question requires combining information from tabs A and B, but you combined A and C. Fix: double-check that you're using the right sources before computing.

*Spending too long on one question.* MSR's pacing risk. Fix: have a walk-away threshold (~3 minutes per MSR question) and respect it.

## Original mini-example

A worked example demonstrating source-mapping on a hypothetical MSR set.

*Hypothetical MSR set.* Three tabs.

*Tab 1 (Description).* "GreenLeaf Inc. operates four warehouses — North, South, East, West — distributing products to retailers across the region. Management is considering a consolidation that would close one warehouse and redistribute its work to the others. Each warehouse has different fixed and variable costs."

*Tab 2 (Warehouse Cost Data).* Table: Warehouse, Fixed Annual Cost ($K), Variable Cost per Unit ($), Annual Capacity (units). Rows: North 200/4/50000, South 300/3/80000, East 250/5/40000, West 350/2/100000.

*Tab 3 (Annual Demand by Region).* Table: Region, Annual Demand (units). Rows: Northeast 30000, Southeast 60000, Mid-region 50000, Pacific 80000.

*Question 1.* "If GreenLeaf consolidates by closing the warehouse with the highest variable cost per unit, by how much will the total annual fixed cost decrease, assuming the closed warehouse's customers are absorbed by the remaining warehouses?"

*Step 1 — Walk the tabs.* Tab 1 = scenario. Tab 2 = cost data per warehouse. Tab 3 = demand by region. Source map built.

*Step 2 — Identify relevant tab.* The question is about closing the highest-variable-cost warehouse and the resulting fixed-cost decrease. Tab 2 has both variable cost and fixed cost. Tab 3 isn't directly needed for this question.

*Step 3 — Process Tab 2.* Highest variable cost is East at $5 per unit. East's fixed annual cost is $250K. If East closes, total fixed cost decreases by $250K.

*Step 4 — Commit.* Answer: $250K decrease.

*Trap to avoid.* The trap on this kind of problem is using Tab 3 (demand data) when it isn't needed. The question only asked about *fixed* cost reduction, not whether the remaining warehouses can absorb East's volume (which would require Tab 3). A student who reads Tab 3 anyway burns time. The discipline of *use only what the question asks* prevents this.

The other trap is mixing up "highest variable cost" (East at $5) with "highest fixed cost" (West at $350K). The question said variable. Reading carefully matters.

*Time spent.* About 90 seconds — most of it in the initial tab walk and the targeted Tab 2 read.

## More worked examples

### Example 1 — Source-mapping on first encounter

*Setup.* MSR set: Tab 1 (description of a non-profit's funding model), Tab 2 (annual budget allocation table), Tab 3 (chart of donations over five years).

*Thinking process.* Walk each tab in 20-30 seconds: Tab 1 describes who the non-profit serves; Tab 2 has expense categories with dollar amounts; Tab 3 shows donation trends. Build the source map: program-context on Tab 1, expense breakdown on Tab 2, revenue trend on Tab 3.

*Solution.* Source map: programs (Tab 1), expenses (Tab 2), revenue (Tab 3).

*Common mistake.* Reading every tab in detail trying to memorize content. By question 1, you've used 90+ seconds and still need to answer — and you'll re-read anyway because you didn't retain enough.

*Takeaway.* The first tab walk is for *cataloging*, not memorizing. Build the map; return to specific tabs as questions demand.

### Example 2 — Cross-source synthesis

*Setup.* Sub-question: "If the non-profit's expenses grew at the same rate as donations did between 2020 and 2024, what would 2024 expenses have been?"

*Thinking process.* Need both Tab 2 (expense data) and Tab 3 (donation growth rate). From Tab 3, calculate donation growth from 2020 to 2024. Apply that growth rate to 2020 expenses (from Tab 2) to get hypothetical 2024 expenses.

*Solution.* Multi-tab synthesis: extract growth rate from one tab, apply to data from another.

*Common mistake.* Computing growth using the wrong tab — e.g., using 2024 expenses from Tab 2 directly without applying the donation growth rate. The question specifies "if expenses grew at the same rate as donations" — that's the projection.

*Takeaway.* Cross-source questions require careful tracking: which fact comes from which tab, which operation goes where. Misattribution is a common DI trap.

### Example 3 — Skipping irrelevant tabs

*Setup.* Sub-question: "What was the largest expense category in 2023?"

*Thinking process.* Only Tab 2 (expense table) is needed. Tab 1 (description) and Tab 3 (donation chart) are irrelevant.

*Solution.* Open Tab 2, find 2023 column, identify the largest value. Done.

*Common mistake.* Re-reading Tab 1 or Tab 3 "just in case" — wastes 30+ seconds with no information value.

*Takeaway.* The source map's purpose is to *exclude* tabs from a query. If a tab doesn't have data relevant to the current question, skip it.
